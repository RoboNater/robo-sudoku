# Project

RoboSudoku: a free, ad-free sudoku game for web + iOS/Android. The architecture and milestone plan live in `dev-notes/development-plan.md` — read it before starting a milestone. Key design rule: fully separate, switchable game UIs live under `src/uis/<name>/`, each optionally declaring its own skins (the `BoardSkin` contract in `src/skins/types.ts`) and layout variants, all sharing one engine (`src/engine/`, pure functions) and game state (`src/state/game-reducer.ts`).

# Workflow

- Work on sequentially numbered milestone branches (`m01-template-updates`, `m02-engine`, …); commit/push as needed. Merging a completed milestone into `main` (with `--no-ff`) and pushing is pre-approved.
- Before merging: `npm test` and `npx tsc --noEmit` must pass. `expo-env.d.ts` is gitignored and only generated by briefly running `npx expo start` — do that once if tsc complains about CSS module imports.
- Engine and reducer changes need jest coverage. Test helper files must live outside `__tests__/` directories (jest-expo treats every file there as a suite); put them in `src/engine/test-utils/`.
- Verify UI changes in the running web app, not just by typecheck (headless Chromium via playwright-core works; see the `run` skill).

# Conventions

- Source under `src/` with the `@/*` alias; TypeScript strict.
- Board/pad components style exclusively from a `BoardSkin` palette, never from `Colors` directly; app chrome (tabs, settings) uses `useTheme()` and the themed components.
- Every skin provides both `light` and `dark` palettes; skins are orthogonal to the system color scheme.
- Platform splits use `.web.ts(x)` files (see `app-tabs`, `use-keyboard-controls`), not `Platform.OS` branches.
- `dev-notes/` holds the user's own notes; don't edit `nates-notes.txt`.
